# Restricted C++ canonical conformance — M0-PR10

`tools/conformance/cpp` is an isolated test executable for the existing v1 and opted-in v2 candidate schemas. It consumes checked-in generated schemas and public fixtures, imports no TypeScript or sibling repository, and exposes no SDK, signer, custody service or production ABI. The authoring bundle, consumer pins and all wire/canonical/signature vectors stay unchanged.

Run `pnpm check:canonical` after the normal repository setup. The existing CI job runs that command with a 75-minute limit for three builds, each bounded to 20 minutes, and three container runs. All adapters execute offline/read-only with dropped capabilities, no-new-privileges, 1 GiB memory, two CPUs, 128 PIDs and a 120-second test timeout (three minutes including startup). Missing tools, build failures, sanitizer failures or absent/duplicate/differing transcript records fail the gate. Ordinary `pnpm check` remains Docker-independent.

The C++20 adapter checks the 1 MiB raw input limit and Unicode scalar validity, validates escaped surrogate pairs before any lossy parsing, then uses jsoncons streaming events with a depth-16 limit. The raw escape guard is necessary because this jsoncons pin can discard a lone low-surrogate escape in an object key. Duplicate decoded names are rejected before inserting the second value. Only strings, arrays and objects are admitted; closed local schemas and exact uint64 parsing precede the same semantic checks as the authoring reference. No network schema resolver is supplied. The restricted RFC 8785 serializer sorts names by UTF-16 code units, preserves Unicode values and implements minimal string escaping with lowercase control hex (the default jsoncons encoder uses uppercase); it implements no JSON-number canonicalization. Accepted input must match the serialized bytes exactly. Shape products are bounded before multiplication; chunk order/totals, positive parameters, timestamp intervals and v2 width/operator coherence are checked separately from JSON Schema.

Five C++ test groups cover nine golden objects, eight public Ed25519 signatures, 32 normative negatives, malformed/overlong/truncated UTF-8, escaped duplicate names/lone surrogates, size/depth boundaries, unknown fields, exact uint64 boundaries, terminal newlines, UTF-16 ordering, Unicode preservation and all control-character escapes. Fixed chunk/blob answers and little-endian framing are checked independently. The runner compares actual canonical bytes, commitments and signature preimages across Rust, Python and C++; it does not merely count successful suites.

The test build is unoptimized to bound template/sanitizer compile cost, matching the native wire harness. An optimized GCC 12 sanitizer build emitted `std::regex` may-be-uninitialized diagnostics; optimized consumer builds remain a separate qualification gate. Compilation uses `-Wall -Wextra -Wpedantic -Werror`, AddressSanitizer and UndefinedBehaviorSanitizer with recovery disabled. These checks instrument the adapter and header-based JSON parser. The schema wrapper is compiled separately with warnings-as-errors and without sanitizer instrumentation to keep the schema-heavy build bounded; the upstream BLAKE3 C library is also not sanitizer-instrumented. No C++ formatter or additional static-analysis gate is configured. Linux conformance establishes neither consumer-platform ABI support nor throughput. Container limits are fixture workload limits, not a proven boundary for malicious code.

## Prior art and dependency boundary

| Project / pattern                                                                                                                      | Decision, license and fit                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [jsoncons v1.10.0](https://github.com/danielaparker/jsoncons/tree/v1.10.0), commit `9e57e421285422d7aeeb5aa7dc839f6a19121ee6`          | Reuse the native wire harness's BSL-1.0 header dependency behind a new bounded SAX/schema wrapper. No additional general-purpose JSON package.                                                             |
| [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785)                                                                                     | Adapt the UTF-16 ordering and number-free escaping pattern in a restricted serializer. A general-purpose JCS implementation is outside this task. No copied upstream implementation or new JCS dependency. |
| [BLAKE3 1.8.7 C implementation](https://github.com/BLAKE3-team/BLAKE3/tree/1.8.7/c), commit `f3149ec5bb5449af877ba20377a11008ff499fa2` | Add the official portable C dependency under its Apache-2.0 licensing option; disable SIMD/TBB for this test build. Kryvola code implements only domain/framing rules.                                     |
| [OpenSSL 3 Ed25519](https://docs.openssl.org/3.0/man7/EVP_SIGNATURE-ED25519/)                                                          | Add a public-signature verifier wrapper using the Debian security-maintained libcrypto package (Apache-2.0). No private key, signing or key generation is used.                                            |

The Docker base is digest-pinned; both source repositories are checked against full commit IDs. CMake and OpenSSL follow the existing native harness's Debian package-update policy rather than claiming bit-identical OS packages. The first build needs network access; runtime does not. All additions stay in test tooling; no root, native wire or consumer dependency changes. Fixed signatures/commitments demonstrate byte compatibility, not producer authorization, time validity, parameter approval, FHE correctness or independent cryptographic qualification. M0 and all assurance profiles remain unqualified. See [canonical contracts](canonical.md), [Rust](canonical-rust.md), [Python](canonical-python.md) and [v2 arithmetic](fhe-q1-arithmetic.md).
