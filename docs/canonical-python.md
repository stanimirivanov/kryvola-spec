# Python canonical conformance — M0-PR9

`tools/conformance/python` is an isolated test adapter for the unchanged historical v1 and opted-in v2 candidates. It imports no authoring implementation or sibling repository. It consumes the checked-in closed JSON Schemas and fixed public vectors; it is not an SDK, signer, key store or trust decision service.

Run `pnpm check:canonical` at the repository root. The existing CI canonical job runs the same command. Both adapters build from digest-pinned Linux images and run without network, on read-only filesystems with dropped capabilities, no-new-privileges, 1 GiB memory, two CPUs, 128 PIDs and a 120-second test timeout. Each image build has a 20-minute runner limit; the CI job allows 50 minutes for both builds, runs and setup. Python uses CPython 3.14.7, uv 0.12.5 and a committed checksum lock; `uv sync --locked --no-build` requires wheels and fails on missing dependencies. The Rust gate still enforces rustfmt and Clippy. Python uses standard-library unittest; no Python lint/type gate is configured. Ordinary `pnpm check` remains independent of Docker. The container limits qualify these fixtures only.

The adapter caps raw input at 1 MiB, decodes strict UTF-8, bounds containers to depth 16 before parsing, rejects decoded duplicate keys through object-pair hooks and rejects JSON numbers, booleans, null and lone surrogates. Independent RFC 8785 serialization must reproduce the input bytes exactly. Generated schemas enforce closed fields and decimal uint64 strings; Python's exact integers implement the shape, chunk, interval, positive-parameter and v2 width/operator checks. An explicit empty schema registry prevents network retrieval. UTF-16 key ordering, unnormalized Unicode, byte/depth bounds, escaped aliases, unknown fields, integer overflow and terminal newlines have regressions.

Five unittest groups reproduce nine canonical objects and eight public fixture signatures and reject all 32 normative negatives plus local mutations. The runner compares nine actual Rust/Python records containing version, kind, canonical bytes, BLAKE3 commitment and signature preimage; missing, duplicated or differing records fail. Both suites independently assert chunk/blob framing against the fixed corpus. SHA-256 build provenance remains distinct from BLAKE3 commitments. These checks establish fixture compatibility, not producer authorization, parameter approval, current-time validity or correct encrypted evaluation. C++ remains M0-PR10; M0 and all assurance profiles remain unqualified.

## Prior art and dependency boundary

| Library                                                                                        | Decision and fit                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [rfc8785 0.1.4](https://github.com/trailofbits/rfc8785.py)                                     | Adopt an isolated Apache-2.0, pure-Python JCS dependency behind the bounded parser; no general number encoding is exposed.                                                                                                                                                            |
| [blake3 1.0.11](https://github.com/oconnor663/blake3-py)                                       | Adopt official Rust-backed Python bindings under the Apache-2.0 option (also CC0); custom code implements only protocol framing. Shares the BLAKE3 implementation family with Rust, so this is language/framing conformance, not independent cryptographic implementation validation. |
| [jsonschema 4.26.0](https://python-jsonschema.readthedocs.io/)                                 | Adapt the existing native Python harness dependency, MIT; use closed local schemas with an explicit registry.                                                                                                                                                                         |
| [cryptography 50.0.2](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/) | Adopt the Apache-2.0/BSD-3-Clause public Ed25519 verifier. Compiled wheel and its transitive dependencies add weight, but avoid handwritten signature verification; only fixed public keys are used.                                                                                  |

The isolated lock resolves ten external packages; no root or native Python dependency changes. Upstream source is not copied. Schema/policy evolution must deliberately update both adapters and their corpus; neither adapter is a normative contract author.
