# Rust canonical conformance — M0-PR8

`tools/conformance/rust` is an isolated, unpublished test crate, not a production codec, receipt service or trust library. It consumes checked-in `generated/canonical/` schemas and fixed `generated/fixtures/canonical-*.json` vectors. No sibling repository, private key or external service is used. The authoring bundle version and every prior wire/canonical/digest/signature vector stay unchanged; only build provenance changes for the new package task and Docker context policy.

Run `pnpm check:canonical` from the repository root after `pnpm install --frozen-lockfile`. Node/pnpm requirements are unchanged. Docker must provide BuildKit, Linux containers and network access during the first image/dependency build; missing Docker, dependencies, components or fixtures fail the gate. The command first checks generated artifacts, then builds the digest-pinned Rust 1.98.1 image with a committed Cargo lock. Build steps run rustfmt, Clippy with denied warnings and test compilation, using locked shared registry/target caches for subsequent source edits. Test execution uses the compiled binary with no network, a read-only filesystem, dropped capabilities, no-new-privileges, 1 GiB memory, two CPUs, 128 PIDs and a 120-second timeout. The runner allows 20 minutes for the image build and three minutes for container startup/execution. Limits qualify this fixture workload only; Docker is not a demonstrated malicious-code security boundary. CI has a separate canonical job; ordinary `pnpm check` remains independent of Docker. No passing skip/fallback is available.

The restricted Serde visitor checks the 1 MiB input bound before UTF-8 parsing, bounds containers to depth 16 during parsing, rejects duplicate decoded keys before inserting a second value and permits only strings, arrays and objects. Serde rejects malformed UTF-8 and lone surrogates. Closed generated JSON Schemas enforce required/unknown fields, decimal uint64 strings and structural bounds; the Rust adapter separately checks shape products without arithmetic overflow, positive parameters, precision, v2 dtype/radix/operator coherence, manifest chunk ordering/totals/expansion bounds and timestamp intervals. Accepted bytes must exactly equal independent JCS serialization, without Unicode normalization, BOM, whitespace or terminal newline.

Tests reproduce all historical v1 and opted-in v2 objects, domain-separated BLAKE3 commitments, operation identity, chunk/blob framing, signature preimages and fixed public-key Ed25519 signatures. They reject both normative negative corpora, wrong domains/versions, malformed parser inputs, unknown fields and structurally valid semantic mutations. The parser is tested directly on duplicate/escaped-alias keys and depth boundaries; it cannot rely on the final JCS comparison to detect erased duplicates. Synthetic UTF-16 property ordering and composed/decomposed string cases supplement the closed schema corpus. Fixture signatures establish byte compatibility, not producer trust, current-time validity, cryptographic parameter approval, cross-object authorization or correct FHE evaluation.

## Prior art and dependency boundary

Exact versions/checksums are in the isolated `Cargo.toml`/`Cargo.lock` (115 resolved packages including transitive dependencies). Serde/serde_json, hex and jsonschema reuse the existing native harness versions/patterns; jsonschema disables default network/file resolver features and loads only checked-in schemas. The adapter's explicit kind/version table is closed and must be updated deliberately if formats evolve. Kryvola semantic policy is mirrored original logic and needs differential maintenance when the authoring validators change.

| Dependency                       | Adoption / license / fit                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `serde_json_canonicalizer` 0.4.1 | New MIT JCS dependency behind the restricted parser/validator wrapper; avoids implementing general JCS ordering/escaping.       |
| `blake3` 1.8.7                   | New official Rust implementation; Apache-2.0 licensing option. Custom code implements only Kryvola framing, not cryptography.   |
| `ed25519-dalek` 2.2.0            | New BSD-3-Clause verifier dependency with default features disabled; only fixed public fixture keys, no signing/key generation. |
| `base64` 0.22.1                  | MIT/Apache-2.0; reuse the native lock's version for strict unpadded fixture signature decoding.                                 |

These dependencies are test tooling, not exported runtime packages or production adoption approval. Registry crates carry upstream license notices; no upstream source is copied into handwritten files. SHA-256 provenance remains distinct from BLAKE3 protocol commitments. Python/C++ canonical adapters remain M0-PR9/10; the existing `pnpm native:check` still covers wire interoperability separately. No assurance profile is enabled and M0 remains incomplete.
