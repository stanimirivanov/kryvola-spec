# Reference and identity previews (M0-PR4)

M0-PR7 adds [opt-in canonical commitments and operation-ID derivation](canonical.md). The unsigned preview IDs/digests below remain illustrative; computed identities require an explicit consumer update.

M0-PR6 adds [real native bindings and conformance](native-wire.md) alongside these unchanged structural previews; deployed semantic/authorization enforcement remains separate.

Bundle `0.1.0-preview.3` adds strict Effect declarations in `src/control.ts`, JSON Schemas and fixtures under `generated/control/` and `generated/fixtures/control.json`, and `generated/proto/kryvola/spec/v1/control.proto`. ArtifactRef v1 and every pre-existing contract artifact retain their bytes and tags. Consumer pins require a separate explicit update.

**BEHAVIOR-ADJACENT:** new decoders require all declared fields, exact version `"1"`, known enum values and no unknown properties, including nested objects. References contain immutable IDs/versions and lowercase 64-character hexadecimal commitments; they grant no access. Digest algorithm/domain binding and operation-ID derivation require the later canonical-format contracts in M0-PR7. Fixture identifiers and digests are illustrative, not computed commitments. These declarations do not enable any assurance profile.

| Contract           | Meaning and boundary                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| KeyContextRef      | Tenant-scoped immutable key-context declaration and key epoch; never a decryption/evaluation key, credential or capability                                 |
| PlanRef            | Tenant-scoped immutable plan identity and digest; no executable bytes                                                                                      |
| DisclosureIdentity | `(tenant_scope, logical_job_id, output_stage, recipient, disclosure_index)`; stable across attempts, launches and recovery epochs; baseline index is `"0"` |
| Operation          | Immutable intent, tenant/job/stage, workflow epoch, policy, deadline and references; public status is a separate observation                               |
| Attempt            | Operation/workflow identity with workflow-authorized attempt epoch and coordinator fence; not the Temporal SDK activity retry count                        |
| Execution          | One physical launch with its attempt, execution ID, session epoch, deadline and physical-state observation                                                 |

All integer fields use canonical ASCII decimal **strings**, range `0..18446744073709551615`, with no sign, leading zeroes, exponent or whitespace. The same lexical bound is exported into JSON Schema. Deadlines are absolute Unix epoch milliseconds; zero is structurally valid and already expired. Decoding never consults a wall clock. Runtime admission/lease decisions use authoritative coordinator time and reject expired requests; unsigned overflow must reject, never wrap.

`workflow_epoch` starts at zero and survives ordinary retries and Temporal Continue-As-New. Coordinated recovery advances it and fences old operations without erasing admission/disclosure tombstones. A new logical attempt advances `attempt_epoch` and its fence; a duplicate pure launch gets a distinct `execution_id` under the same attempt. Fences are coordinator-issued, not caller-controlled authorization. Session epoch zero denotes baseline pure execution; interactive profiles must define fresh authorized session epochs and one-use preprocessing rules before enablement. Counter exhaustion fails closed.

The operation idempotency key is a non-secret deduplication label scoped by tenant/job; retries must bind the same immutable intent, with conflicts rejected by the future coordinator. `decodeOperation` checks tenant agreement of references/disclosure and logical-job agreement. `checkExecutionContext` checks tenant, operation, workflow epoch and exact deadline correlation. It **does not** establish the current attempt, fence, lease, policy validity, unique launch, cryptographic integrity or release permission. Other decoders validate structure only. JSON Schema alone does not enforce these cross-object equality rules.

Public result statuses are exactly `COMPUTE_SELECTED`, `EVIDENCE_PENDING`, `EVIDENCE_VERIFIED`, `RELEASED`, `EVIDENCE_FAILED`, `CANCELLED`, `EXPIRED`. No result status is implied before selection or a terminal coordinator decision. Physical observations are `CREATED`, `RUNNING`, `SUCCEEDED`, `FAILED`, `CANCELLED`, `EXPIRED`; `SUCCEEDED` never means selected, verified or released. Matching cancellation/expiry labels do not establish a committed tombstone. This PR defines vocabulary, not legal transitions or a state machine.

The Protobuf preview uses explicit stable tags and presence-bearing `optional string` scalars (including decimal integers and enum strings); nested messages also carry presence. Native decoders must check required presence, canonical ranges, enums, versions and unknown fields before use. Protobuf bytes are not canonical signing bytes. This preview has no native codecs, RPC endpoints, persistence, grants, ciphertext transport or authentication. M0-PR5 defines bounded engine/events; M0-PR6 supplies native bindings/conformance; M0-PR11/12 specify durable transitions and fences. No later-milestone stub is introduced here.

`pnpm check` covers strict decoding, uint64/regex boundaries, context mismatch, status separation, generated schemas/fixtures/provenance, explicit tags and Buf checks. Legacy regression hashes remain pinned to the pre-refactor revision as an unchanged subset; new artifacts are separately checked. Live deadline enforcement, monotonic fencing, disclosure uniqueness and malicious-worker authorization remain unimplemented runtime gates.
