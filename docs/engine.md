# Bounded Engine API and events (M0-PR5)

M0-PR6 adds [native message/RPC bindings and conformance](native-wire.md); the limitations below describe this original contract preview. Production adapters and authorization remain unimplemented.

Bundle `0.1.0-preview.4` adds `src/engine.ts` and `src/transport.ts` as explicit submodules; import their built declarations from `dist/engine.js` and `dist/transport.js`. They reuse the root ArtifactRef and control contracts without a circular root re-export. All previous contract bytes/tags remain unchanged. No dependencies, native runtime packages or consumer pins change.

The generated `EngineService` follows [gRPC unary service definitions](https://grpc.io/docs/what-is-grpc/core-concepts/): `GetCapabilities`, `Execute`, `GetExecutionStatus`, `CancelExecution`. Effect owns logical schemas/fixtures and explicit stable tags; the generator exports JSON Schema and `engine.proto`, including bounded repeated strings/references and imported identity messages. Wire schemas do not enforce all constraints. Native presence/unknown-field validation and cross-language conformance remain M0-PR6; no service or fake runtime engine is implemented.

| RPC                | Semantics and retry boundary                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GetCapabilities    | Untrusted advertisement of engine/parameter digests, allowlisted program digests, FHE-Q1 profile, ADD/MUL exact modular arithmetic and capacity. This does not enable or qualify an assurance profile.                                                                                                                                                                                                                     |
| Execute            | Acknowledges physical launch metadata, not selected output. `validateExecuteRequest` checks exact engine/parameter/program support, required operators, CREATED pure intent/session zero, operation/execution correlation, input tenant/size and deadline against supplied authoritative time. Authentication, signed plan/policy, current authorization/fence/lease and capacity reservation remain mandatory at runtime. |
| GetExecutionStatus | Poll exact `(tenant, operation, workflow_epoch, attempt_epoch, fence, execution_id)` after ambiguous submit; never transparently create a new attempt. Returned output references are unselected candidates, with owner access still quarantined.                                                                                                                                                                          |
| CancelExecution    | Idempotent cancellation ID bound to the exact target. REQUESTED means accepted request, OBSERVED_STOPPED means physical process observation, NOT_FOUND is no knowledge; none establishes public CANCELLED. Public acknowledgement requires the coordinator's committed tombstone/fence barrier.                                                                                                                            |

Execute retries with the same physical execution ID and identical immutable request must return the existing launch; conflicting reuse rejects. A fresh physical ID is a separate pure launch, permitted only under workflow/coordinator authorization. Deadlines do not extend on retry. RPC deadlines/cancellation do not roll back effects; query/reconcile before resubmitting. Interactive side effects are unsupported. Engine status responses must match every requested target field; stale/wrong-target observations are rejected by consuming adapters/registry, not promoted to selection. Fences/leases cannot be validated from advertisements or DTOs alone.

RPC failures use gRPC status, with bounded sanitized diagnostics: INVALID_ARGUMENT/UNIMPLEMENTED/FAILED_PRECONDITION for invalid/unsupported intent (no automatic retry); DEADLINE_EXCEEDED/CANCELLED terminate the physical request; RESOURCE_EXHAUSTED/UNAVAILABLE permit bounded backoff/reconciliation within the existing deadline. INTERNAL requires investigation and reconciliation before any pure retry. Observation `error_code` describes physical failure, not a public job verdict. Success/running/created require NONE; failed/cancelled/expired require a non-NONE reason. Only SUCCEEDED may carry nonempty ciphertext candidate references. No detailed exception, proof, key or credential fields are accepted.

`ExecutionObservedEvent` v1 contains event/causation IDs, aggregate sequence, immutable operation context and an execution observation. `decodeExecutionEvent` validates identity/deadline correlation, output tenants and observation consistency. Partition by opaque tenant/logical-job identity from the operation; order applies only within that partition. Consumers authenticate producers, durably deduplicate event ID, check sequence and current registry/fence, quarantine sanitized poison metadata and acknowledge only after durable handling. Events are advisory observations, never commands, release authority or exactly-once guarantees. Missed notifications require durable polling/reconciliation.

Byte guards accept **actual serialized Uint8Array views**, not objects, character counts or compressed-size estimates. `assertControlBytes` caps each uncompressed decoded control DTO at 65,536 bytes before RPC/Ray submission; receiver transport limits must reject oversized frames before materialization and recheck decoded size. `assertEventRecordBytes` caps the **entire uncompressed encoded record**, including value, key, headers and record framing, at 65,536 bytes; passing only the Protobuf value is incorrect. Adapters must budget their record format and refuse extra headers after checking. `assertTemporalCallBytes` caps each encoded logical payload at 32,768 bytes and the payload sum plus separately supplied application metadata at 131,072 bytes. Include payload encoding metadata, headers and envelope overhead exactly once; cover inputs, outputs, signals, heartbeats, failures and search attributes. Large structures become immutable artifact references; compression/encryption never bypasses the logical budget.

Tests exercise exact/one-byte-over limits using serialized UTF-8 fixtures, multibyte text, byte views, aggregate overhead and strict negotiation/event boundaries. They are byte-budget/reference tests, **not native Protobuf/Kafka/Temporal codec conformance or deployed adapter enforcement**. Actual framed wire vectors and transport hooks remain M0-PR6 and the later fabric integration tasks. Canonical signing, coordinator state transitions, qualified profiles and release authorization remain separate gates.

**BEHAVIOR-ADJACENT / preview compatibility:** OpenAPI removes ADMITTED from HTTP 200's seven public result states. An admitted job with no selected result/terminal verdict returns HTTP 202 with job ID; clients must handle this response and poll with backoff. HTTP 200 CANCELLED still requires the committed coordinator barrier. This documentation API has no deployed server. `pnpm check` validates these schemas, generation, limits, status enum agreement, Buf and Redocly outputs.
