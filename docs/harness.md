# Development harness and enforcement

| Requirement/source                                    | Governed files                                 | Enforcement / command                                                                   | Limit or manual review                                                                       |
| ----------------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| User schema-stack amendment / ADR 0001                | `package.json`, `src/`, `openapi/`             | Exact lock, `pnpm typecheck`, `pnpm openapi:check`, `pnpm openapi:build`                | Schema semantics and API support remain reviewer judgments                                   |
| Design 4.3: spec has no runtime repository dependency | `package.json`                                 | `pnpm architecture:check`; isolated passing/failing manifest fixtures in `pnpm test`    | Dynamic JS imports are reviewed; this check does not claim whole-program dependency analysis |
| Design 6: references only / bounded profile           | `src/index.ts`                                 | Positive/negative fixtures in `pnpm test`; strict extra-field decoding and 1 GiB policy | No native decode, encryption, authorization or expanded-memory admission yet                 |
| Design 6: versioned portable contracts                | `tools/generate.mjs`, `generated/`, `buf.yaml` | `pnpm generated:check`, `pnpm proto:check`; explicit stable tags                        | Structural projections are not Protobuf codecs; future fields require generator extension    |
| Plan reproducibility and supply chain                 | Versions, lock, `pnpm-workspace.yaml`          | `pnpm install --frozen-lockfile`; exact Buf build approval; CI `foundation / verify`    | Dependency vulnerability/license review beyond baseline Apache-2.0 remains M0 work           |
| Codex essentials                                      | Root `AGENTS.md`                               | Located at Git root; no nested overrides; commands match CI                             | Trust/activation is managed by the user's client; no config is assumed active                |

Fast check: `pnpm check:fast`. Full foundation check: `pnpm check`. Neither silently skips absent tools/inputs. Formatting fixes use `pnpm format`; generated drift uses `pnpm generate`, then rerun the affected checks. Required expensive crypto/hardware/security tests are deferred, not represented by a no-op passing command.

CI is configured for pull requests and main pushes, with commit-pinned actions, read-only contents access and no persistent checkout credentials. Local results and CI configuration are distinct; no hosted CI result is claimed without observation. A maintainer must configure branch/ruleset protection to require `verify`, review requirements and any desired secret scanning. No remote protections are changed by this PR.
