# Native wire generation and conformance (M0-PR6)

The current conformance runner targets Linux/amd64. `native/compiler.cmake` builds the gRPC plugin host's generic/C++/Python compiler helpers; full protoc is the checksum-verified upstream executable. This toolchain is for conformance, not a published complete compiler SDK.

Bundle `0.1.0-preview.5` adds real compiled Rust, Python and C++ Protobuf codecs and Engine gRPC client/server stubs under `bindings/`. Effect remains the sole non-OpenAPI authoring source; `generated/proto/` is the input to native generators. The old `generated/{rust,python,cpp}/artifact_ref.*` files remain unchanged structural previews. Consumer pin updates and release packaging are separate tasks: native consumers must explicitly vendor/check `bindings/` plus its provenance, not assume the old structural files became codecs.

Run `pnpm generate` after an Effect change, then `pnpm native:generate` to export native code, descriptors, schema-policy data and golden vectors. `pnpm native:check` regenerates into ignored cache, compares every file/hash, compiles the committed-equivalent bindings, runs all three codecs against shared positive/negative wire cases and exercises a loopback fake Engine service. Docker with Linux containers is required; native host toolchains are not required. Cold bootstrap compiles upstream gRPC/Protobuf and is intentionally a separate CI job. `pnpm check` checks native source/artifact provenance without starting Docker; it does not substitute for the native gate. Missing Docker/dependencies fail, never skip. No hosted CI result is implied by configured jobs.

These additions are native build/conformance dependencies, isolated from the existing pnpm dependency graph and runtime repositories. Cargo/uv locks pin transitive resolution; Docker base images are digest-pinned and upstream source/submodule identities are checked. OS package security updates remain distribution-managed: this is reproducible generated output, not a claim of bit-identical OS images. Full transitive legal/security qualification remains part of the existing unratified M0 review. The C++ bootstrap uses unoptimized compilation to reduce conformance build cost; this gate provides no performance results.

Each boundary wrapper checks a known message type, rejects oversized wire input, recursively rejects unknown fields, applies the exported JSON Schema to decoded fields, and enforces the existing ArtifactRef 1 GiB decoder policy. Native schema-policy data is generated from Effect and the current limit. Encoding validates source JSON before ProtoJSON conversion can coerce values. Presence-sensitive scalars remain optional Protobuf fields; repeated fields have no presence bit, so empty lists are governed by list cardinality. Raw generated parsers alone are permissive and must not be used as Kryvola validation boundaries.

Golden cases cover all published reference, control, RPC and event messages, exact uint64/ArtifactRef maxima, and a valid 65,536-byte ExecuteRequest. Negative cases include nested/top-level unknown fields, unsupported versions, missing required data, noncanonical/overflowing decimal values, invalid list sizes, malformed/truncated wire and a valid 65,537-byte request. The same cases run through all languages; Rust also round-trips generated concrete message types after reflection validation. Golden bytes establish conformance for these pins, **not canonical Protobuf signing bytes**. The input/source/file hashes in `bindings/manifest.json` establish build provenance only.

The fake service is loopback-only, ephemeral, carries fixtures only and runs with external networking disabled. Rust and Python make real gRPC calls; Python exercises all four methods and explicit deadline/profile rejection. C++ RPC bindings compile against the pinned headers; C++ gRPC runtime linkage/live calls remain a consumer-integration gate. Its REQUESTED cancellation response is not a public CANCELLED verdict. Both server and smoke clients bound message sizes. It is a protocol test fixture, not a durable engine, admission gate or authentication implementation.

Native structural validation does not implement Effect's cross-object equality/reference negotiation functions or the coordinator's current attempt/fence/lease, idempotency store, event sequence/deduplication or release transaction. Native fabric/engine adapters must independently enforce these semantic rules when implemented. No TypeScript runtime is required or introduced in native processes. Transport hooks must still enforce whole-record headers/framing and Temporal aggregate budgets; this PR tests control codec limits, not deployed Kafka/Temporal adapters. Cryptographic payload decoding, signatures, evidence correctness, TLS identity/grants, production server implementation, consumer pins and qualification remain later gates. No assurance profile is enabled.

The strict codec wrappers are conformance boundaries, not automatically installed gRPC interceptors. In particular, standard Prost decoding discards unknown fields: Rust service/client adapters must validate raw bytes before typed decoding through a validating codec/transport boundary. Checking a re-encoded typed message is insufficient to detect discarded fields. The loopback smoke test checks generated RPC interoperability; the negative wire tests exercise the strict wrappers directly.
