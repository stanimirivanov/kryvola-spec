# Experimental contract publication

The manual main-only `.github/workflows/release.yml` publishes committed contract
and native projection bundles after `pnpm check`, `pnpm check:canonical` and
`pnpm native:check`. No release is made by a push or pull request. Only the final
publisher gets contents-write/OIDC. Dispatch is a separate maintainer action.

`node tools/release.mjs install` explicitly installs checksum-pinned Linux x64
Cosign 3.1.3 under ignored `build/release-tools`. It is an Apache-2.0 build tool,
not a runtime dependency. The pin and publisher pattern follow existing fabric
publication. `node tools/release.mjs qualify` requires a clean committed checkout
and fresh `build/publication`. It validates committed generated/native manifest
files and source hashes, compares two independent `git archive` invocations and
packages generated/, bindings/, LICENSE, package/lock and Node pin metadata.
This checks deterministic packaging of already generated bytes, not independent
compiler/generator reproducibility. The archive is a projection distribution,
not a complete rebuild kit; referenced sources remain at the publication commit.

The publication commit and provenance of the underlying contracts are distinct.
Contract source/tool pins remain in the bundled manifests; a later publisher
commit does not silently relabel those inputs. The signed publication manifest
binds archive and in-toto/SLSA-v1-shaped provenance bytes. No SLSA assurance level,
SBOM completeness, reviewer approval or cryptographic capability is asserted.
Local qualification exercises real ephemeral signatures, a wrong signer and
valid-but-altered manifest bytes; private keys and test signatures are excluded.

The publisher signs keylessly and verifies exact workflow identity, GitHub issuer,
source SHA and workflow_dispatch trigger. Releases use experimental-FULL_SHA,
upload to a draft once and refuse existing tags/releases. Failed drafts require
maintainer inspection; do not overwrite/retry them blindly. Server-enforced
immutability and branch protection remain maintainer settings.

Download the four explicit release assets into one directory, independently select
the expected full publication source, install Cosign, then run:

```sh
node tools/release.mjs verify DOWNLOADED_DIRECTORY EXPECTED_FULL_SOURCE_SHA
```

Verification rejects changed/missing/extra assets, unsafe files, wrong source or
publisher and invalid signatures. Never trust a candidate-selected key or a tag
alone. It does not extract the archive or authenticate specialist review. Consumer
contract adoption still requires its own pinned provenance checks. Publication
leaves M0 ratification pending and profiles disabled.
