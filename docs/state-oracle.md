# Versioned state-model test oracle

M1-PR9-R1 exports existing attempt and disclosure/recovery rules as test-only JSON.
It adds no runtime authority, crypto claim, production admission or new dependency.
See [ADR 0005](adr/0005-state-model-oracle.md) and the original
[attempt](state-attempts.md) / [release](state-release.md) model assumptions.

## Artifact and trace formats

`pnpm generate` owns these files under `generated/state/v1/`:

| Files                                               | Meaning                                                                                    |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `attempts.oracle.json`, `release.oracle.json`       | Complete reachable finite graphs, including rejected/self transitions.                     |
| `attempts.traces.json`, `release.traces.json`       | Positive traces derived from the existing model fixtures (3 and 6 scenarios respectively). |
| `StateOracle.schema.json`, `StateTrace.schema.json` | Effect-authored structural contracts; graph semantics still come from the model.           |

Each `kryvola-state-oracle-v1` graph has `purpose: BOUNDED_MODEL_TEST_ONLY`, a
`model` name, model `bounds`, exact `source_sha256` inputs, sorted action/outcome
vocabularies and `initial: 0`. `nodes[i].state` is the full abstract JSON state;
`nodes[i].edges` contains `[actionIndex, outcomeIndex, targetNodeIndex]` triples.
Exploration uses the existing model's `initial/actions/step/violation` functions,
without copying their guards. State IDs follow deterministic breadth-first discovery.
The exporter fails on invariant violations, state-cap exhaustion or a 16-MiB artifact;
it never truncates the graph. Current graphs contain 2,718 / 2,432 states and occupy
about 3 MiB together; compact integer edge vocabularies limit distribution weight.

A `kryvola-state-trace-v1` object names its `model`, binds exact oracle file bytes
(including the trailing newline) through `oracle_sha256`, and supplies nonempty
`steps`: `{action, outcome, state}` after each observed atomic action. Starting at
node 0, find the unique outgoing edge for `action`, require the expected outcome
and complete target state, then advance to its target. JSON object key order is
irrelevant; array order and every state field matter. Unknown versions/fields,
empty traces, missing edges, changed fences/states, outcomes or ordering fail.
`checkStateTrace` is Spec's generic reference checker, not a runtime dependency.

## Consumption and evidence boundaries

Authenticate an independently selected immutable publication commit through the
[existing release verifier](publication.md), then verify the graph's file SHA-256
against `generated/manifest.json` (and the trace's oracle binding). Source hashes
bind the model and exporter; they do not themselves authenticate the publisher.
Existing native provenance also binds generated bytes. The release bundle carries
all six files; consumers need JSON/hash/graph traversal, not sibling model source,
TypeScript, Effect or a Fabric-to-Spec runtime dependency. Publication remains manual;
this PR neither publishes nor changes a consumer pin or historical signed formats.

The future Fabric adapter must retain raw SQL observations and its mapping beside
its trace. Map one operation's epochs/fences/execution IDs consistently and
injectively into model bounds; never renumber each snapshot or discard a wrong
fence. Map database time without reversing lease/deadline comparisons. Include
rejections and preserve action/commit order; no cherry-picking or invented outcomes.
Workflow/scheduler effects require explicit adapter evidence. An abstract graph
match cannot prove that mapping, SQL isolation, tenant/auth/context/policy binding,
cryptography, fairness or unbounded behavior. Those need the owning Fabric tests.
The release graph's verify/authorization/reconciliation inputs remain assumptions,
not implementations or release permission. Out-of-bound scenarios cannot earn credit.

`pnpm check:state` retains both existing exhaustive safety/mutation checks and now
runs `pnpm check:oracle` (build plus generated graph/sample freshness and trace checks).
`pnpm check` additionally tests every exported edge against its source model and
corrupted traces, and checks generated/native provenance. Breaking format changes
need a new format/path version; model revisions require new source/artifact pins.
Stopping consumption or reverting the additive export removes this evidence only.
